## Repository purpose

Formal (Lean 4 + Mathlib) and documentary investigation of the Collatz problem via the accelerated map, aimed at excluding Type-II divergent orbits. 1687 human-written declarations across 97 modules; dependency closure 7408 nodes.

## Mathematical spine

- **Deficit recursion (pure algebra)** — Delta_{k+1} = Delta_k + b_{k+1} - d_k, where b is the Beatty gap and d the valuation digit. Its Lean proof is `unfold deficit; push_cast; ring`. This is the canonical example of a recurrence that looks dynamical and carries no information -- see the coordinate-change gate.  
  *EOC/CurryFoundation.lean · `EOC.CurryFoundation.deficit_succ`*
- **Deficit increases by at most one per step** — Delta_{k+1} <= Delta_k + 1 whenever every digit is at least 1, so Delta -> infinity requires infinitely many steps with Beatty gap 2 and digit 1, each buying one unit. Corollary of the recursion and the Beatty gap; not an obstruction.  
  *EOC/CurryFoundation.lean · `EOC.CurryFoundation.deficit_succ_le`*
- **FiniteValuationWord (the central datatype)** — The valuation-word abstraction on which most of the library is built; by a wide margin the most depended-upon EOC declaration (425 reverse dependencies inside EOC).  
  *EOC/FiniteValuationWord.lean · `EOC.FiniteValuationWord`*

## Major reductions

- **Drift tends to minus infinity under Curry** — R_N -> -infinity for every reciprocally-summable accelerated orbit. Labelled CURRY + ELEMENTARY CONSEQUENCE in the foundation document: not stated by Curry, but a short rigorous consequence via the Eliahou-Rozier identity.  
  *EOC/CurryFoundation.lean · `EOC.CurryFoundation.R_tendsto_atBot`*
- **Deficit divergence is equivalent to drift divergence** — R'_k = -Delta_k - {k*alpha} with the fractional correction bounded in (-1,0], so R'_k -> -infinity is exactly Delta_k -> infinity. This is the coordinate identity that lets the Curry sector be studied in deficit coordinates at all.  
  *EOC/CurryFoundation.lean · `EOC.CurryFoundation.deficit_tendsto_atTop_iff`*

## Conditional foundations — read the hypothesis before using

- **Curry hypothesis (ReciprocalSummable)** — Summability of the reciprocals along the orbit. Everything in the Curry sector is conditional on this and must be labelled as such -- it is an assumed input, not a theorem of the repository.  
  *EOC/CurryFoundation.lean · `EOC.CurryFoundation.ReciprocalSummable`*
- **Curry normalization to the zero corridor** — Conditionally on Curry, a hypothetical Type-II orbit can be restarted at the last global drift maximum so that R_0 = 0 and R_N < 0 for N >= 1, hence S_N <= floor(N*alpha) and the deficit is non-negative. This is the normalization every later Curry-sector argument assumes.  
  *EOC/CurryFoundation.lean · `EOC.CurryFoundation.zero_corridor_tail`*

## Known equivalences — do not relabel these as new problems

- **Bounded prefix realizers = positive-integer realizability** — sup_N r_N < infinity  <=>  the infinite valuation word has a positive-integer realizer  <=>  r_N is eventually constant. Unconditional, and independent of the Curry sector. Consequence: qualitative unbounded-realizer growth is NOT an easier target than positive-integer realizability, and must not be pursued as if it were.  
  *EOC/ZCRERealizerGrowth.lean · `EOC.ZCRERealizerGrowth.boundedPrefixRealizers_iff_positiveRealizer`*
- **Least prefix realizer stabilizes** — Bounded least-prefix-realizers are eventually constant. For an actual positive seed m_0 this means r_N = m_0 once 2^{S_N+1} > m_0 -- an extremely rigid signature, but not a mechanism for forbidding stabilization.  
  *EOC/ZCRERealizerGrowth.lean · `EOC.ZCRERealizerGrowth.leastRealizer_eventually_constant_of_bounded`*

## Research protocol

Full text in `research-index/research_protocol.md`. The gate that has paid for itself twice:

> Before developing a proposed quantity `X_N`, ask whether it is **independently constrained** or a **deterministic function** of data already fixed (the digit word, the orbit state). If the latter, any recurrence you derive for it will be provable by `unfold; ring`, and it restricts nothing.

This is a screening heuristic, not a proof of equivalence.

## Expansion instructions

Do **not** read the repository breadth-first. Start here, then:

- for a specific question, run `python3 -m tools.research_context query -q "…"` and open only what it names;
- for the formal shape of a result, open the declaration cited above and read its statement, not its proof;
- for research status and non-claims, `docs/RESEARCH_STATUS.md` and the `## Non-claims` section of the relevant audit;
- for what has already been ruled out, `docs/ZERO_CORRIDOR_REALIZABILITY_FRONTIER.md` §27 and §28;
- `research-index/formal_graph.json` has file and line for every declaration.

## What this index cannot tell you

- whether a proof is *correct* — only Lean's kernel does that;
- whether a documented status is still accurate if the docs have drifted;
- anything about routes nobody wrote down. Absence here is not evidence of absence.
